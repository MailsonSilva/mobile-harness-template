📋 Documento de Requisitos do Produto (PRD) — LotaeNome do Projeto: LotaeVersão: 1.0.0Stack Técnica: React Native (Expo) + TypeScript + Supabase + Zustand + NativeWindHarness Target: Pi Coding Agent + Cockpit Visual (mobile-harness-template)🎯 1. Visão Geral & Proposta de ValorO Lotae é uma plataforma móvel desenvolvida para otimizar e automatizar a gestão de lotações, transporte, reservas e controlo operacional de rotas.Objetivos do Sistema:Digitalização de Operações: Eliminar processos manuais na alocação de lugares, registo de passageiros e escalas de veículos.Sincronização Offline-First: Permitir operações em áreas com conectividade oscilante, sincronizando dados assim que a ligação com o Supabase for restabelecida.Segurança e Privacidade: Garantir controlo estrito de acessos via Row Level Security (RLS) e encriptação local de tokens de sessão.👥 2. Personas & Níveis de AcessoPassageiro / Utilizador Final:Consulta rotas disponíveis, horários e vagas.Realiza reservas e recebe confirmações digitais.Motorista / Operador:Visualiza a escala do dia e a lotação do veículo em tempo real.Realiza o check-in ou validação de passageiros na embarcação/veículo.Gestor / Administrador:Gere frota, motoristas, rotas, tarifas e relatórios operacionais.📱 3. Épicos & Mapeamento de Funcionalidades (Features)Épico 0: Bootstrapping do Harness (F-00)F-00: Ingestão do PRD e geração autônoma da matriz de tarefas (feature_list.json).Épico 1: Autenticação & Perfil de Utilizador (F-01)F-01.1: Tela de Login e Cadastro com validação estática de dados (Email, Senha, Perfil).F-01.2: Autenticação via Supabase Auth e persistência segura do JWT via expo-secure-store.F-01.3: Gestão de perfil com suporte a níveis de permissão (Passageiro, Operador, Admin).Épico 2: Gestão de Lotações & Rotas (F-02 - Core)F-02.1: Listagem dinâmica de rotas operacionais com indicação visual de lotação (Vagas Disponíveis / Esgotado).F-02.2: Painel do Operador para atualização de estado do veículo (Em Trânsito, Concluído, Atrasado).F-02.3: Camada de serviço centralizada (LotaeService.ts) e gestão de estado global com Zustand.Épico 3: Reservas & Validação de Check-in (F-03)F-03.1: Fluxo de reserva de lugares com atualização em tempo real no banco de dados.F-03.2: Validação de bilhete/reserva via código de validação ou QR Code.F-03.3: Tratamento visual de estados (Skeleton Shimmer para carregamento, Empty State quando não houver vagas).🛠️ 4. Regras Arquiteturais Invioláveis (Mechanical Enforcers)Todas as alterações efetuadas pelos agentes de IA devem obedecer estritamente às diretrizes de architecture.md:Unidirecionalidade de Dados: Types ➔ Config ➔ Store ➔ Service ➔ UI.UI Isolada: A camada de UI (src/screens/ e src/components/) está proibida de importar o cliente do Supabase diretamente. Toda a interação deve ser intermediada pelas Stores ou Services.Zero any: Não são permitidas tipagens fracas ou ocultadas. Todos os schemas do Supabase devem ser tipados via npm run supabase:types.Testability Compulsória: Todos os elementos clicáveis e inputs da UI devem incluir obrigatoriamente a propriedade testID (ex: testID="btn-reservar-lotae").🧪 5.
